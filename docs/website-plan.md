# 多 APP 官网架构方案

当一个开发者或公司拥有多个 APP 时，官网的组织架构通常有以下三种常见方案。

---

## 方案一：一个主站 + 多个子页面 ✅ 当前选用

**结构示例：**

```
yuntai.tech/                  → 主站首页（品牌介绍 + APP 列表）
yuntai.tech/growbook/         → GrowBook 应用详情页
yuntai.tech/growbook/privacy  → GrowBook 隐私政策
yuntai.tech/app2/             → 未来第二个 APP
yuntai.tech/app2/privacy      → 第二个 APP 隐私政策
```

**优点：**
- 维护成本最低，只需一套代码和一个仓库
- 共享导航、页脚、样式等公共组件
- SEO 权重集中在一个域名下，有利于搜索排名
- 添加新 APP 只需创建一个新的子目录
- 部署简单，一次部署覆盖所有页面

**缺点：**
- 所有 APP 共用同一套设计风格，个性化程度较低
- 单个 APP 出问题可能影响整站

**适合场景：** 中小型团队、个人开发者、APP 数量 < 10 个

---

## 方案二：一个主站 + 子域名

**结构示例：**

```
yuntai.tech/                  → 主站首页（品牌介绍）
growbook.yuntai.tech/         → GrowBook 独立站点
growbook.yuntai.tech/privacy  → GrowBook 隐私政策
app2.yuntai.tech/             → 第二个 APP 独立站点
```

**优点：**
- 每个 APP 可以有独立的设计风格和品牌形象
- 技术栈可以不同（一个用 React，另一个用 Vue）
- 独立部署，互不影响
- 看起来更专业

**缺点：**
- 需要为每个子域名配置 DNS 解析
- 维护多套代码，工作量成倍增加
- GitHub Pages 免费版不直接支持子域名（需要多个仓库）
- SSL 证书需要覆盖通配符域名（*.yuntai.tech）

**适合场景：** 中型团队、APP 之间差异较大、需要独立品牌形象

---

## 方案三：每个 APP 独立官网

**结构示例：**

```
yuntai.tech/                  → 公司主站
growbook.app/                 → GrowBook 独立域名
myapp2.com/                   → 第二个 APP 独立域名
```

**优点：**
- 完全独立的品牌形象和设计
- 可以针对不同市场做独立 SEO 优化
- 一个站点出问题完全不影响其他
- 适合打造独立品牌的明星产品

**缺点：**
- 每个 APP 都需要购买独立域名（费用增加）
- 维护成本最高，每个站点独立管理
- 难以建立统一的品牌认知
- 需要管理多个仓库、多个部署流程

**适合场景：** 大公司、明星产品、不同产品面向不同用户群体

---

## 选择建议

| 因素 | 方案一（子页面） | 方案二（子域名） | 方案三（独立域名） |
|------|:---:|:---:|:---:|
| 维护成本 | 低 | 中 | 高 |
| 域名费用 | 1 个域名 | 1 个域名 | N 个域名 |
| 部署复杂度 | 简单 | 中等 | 复杂 |
| 品牌独立性 | 低 | 中 | 高 |
| SEO 效果 | 集中 | 分散 | 独立 |
| 适合 APP 数量 | 1-10 | 3-20 | 1-5 个重点产品 |
| GitHub Pages 支持 | 直接支持 | 需多仓库 | 需多仓库+多域名 |

**当前选用方案一**，原因：个人/小团队开发，APP 数量有限，维护成本优先，一个仓库管理所有内容最高效。后续如果某个 APP 成为明星产品，再考虑升级为方案二或方案三。
